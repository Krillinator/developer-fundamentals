Docker - Module 03

Overview

So far, we've learned how to build images and run containerized applications using Docker on our local machine.

But running a few containers locally is very different from running applications in production.
Imagine our application needs to run across several machines.

Suddenly, we have new problems to solve:

  • Where should each container run?
  • What happens if a container or machine fails?
  • How do we keep the application available?
  • How do we scale the application?
  • How do we collect logs across multiple containers and machines?

Managing all of this manually would quickly become difficult.
This is where container orchestration comes in.

Container Orchestration

Container orchestration helps us manage containerized applications across multiple machines.

Some of the problems orchestration can help us solve include:

  • Scheduling services across distributed nodes
  • High availability
  • Reconciliation
  • Scaling
  • Logging

There are several orchestration solutions available.
One of the most widely used is Kubernetes.
But before we move on to Kubernetes, we're going to explore orchestration using Docker Swarm.

Docker Swarm

Docker Swarm is an orchestration tool built into Docker Engine.
Instead of managing containers individually on a single machine, Docker Swarm allows multiple Docker hosts to work together as a cluster.

This gives us a simpler environment for exploring some of the ideas behind container orchestration before moving on to Kubernetes.

So far, we've managed individual containers. Now we're going to start managing containers across multiple machines.

Multiple Machines

To properly explore orchestration, we need more than one Docker host.
Instead of installing and configuring Docker across several physical machines or virtual machines, this lab uses Play with Docker.

Play with Docker provides temporary Docker environments where we can create multiple nodes and experiment with Docker Swarm directly from the browser.

Visit:
https://labs.play-with-docker.com/

Prerequisites

Before continuing:

  • Complete Module 02
  • Have a Docker Hub account
  • Be familiar with the Docker commands used in the previous modules
  • Open Play with Docker

What Did We Learn?

Before starting the hands-on work, we now understand why orchestration becomes necessary.

Running containers in production introduces problems that don't appear when we're simply running a container on our own computer.

Container orchestration helps manage those problems across multiple machines.

In this module, we'll begin exploring those concepts using Docker Swarm before eventually moving on to Kubernetes.
