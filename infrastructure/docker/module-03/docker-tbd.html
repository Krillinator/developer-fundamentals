Create Three Virtual Machines

A Docker Swarm consists of multiple nodes.
For our lab, each node will be an independent Ubuntu Server virtual machine.

Create three virtual machines using the Ubuntu Server ISO we downloaded earlier.

Host Computer
│
├── Node 1
├── Node 2
└── Node 3

Use the same basic CPU, memory, disk and network configuration for all three.

Tip

You don't need to download Ubuntu Server three times.

The same ISO can be used to install Ubuntu on multiple independent virtual machines.

Give Each Machine a Hostname

During the Ubuntu installation, give each machine a different hostname.

Use:

node1
node2
node3

This makes it much easier to tell which machine we're currently working with.

After installation, our environment should look like:

node1
Ubuntu Server

node2
Ubuntu Server

node3
Ubuntu Server

These machines aren't part of a Docker Swarm yet.

Right now, they're simply three independent Linux machines.

Update Ubuntu

Start all three virtual machines.

On each node, update the available package information:

sudo apt update

Then install available updates:

sudo apt upgrade -y

We're going to install Docker on every machine, so repeat the following Docker installation steps on:

node1
node2
node3

Install Docker Engine

Our nodes currently have Ubuntu Server, but that doesn't automatically make them Docker hosts.

Each machine needs Docker Engine.

We'll install Docker using Docker's official apt repository.

Note

Docker Engine is what actually runs and manages containers on our Linux machines.

We don't need Docker Desktop inside these Ubuntu Server VMs.

Add Docker's Repository

First, install the packages needed to access Docker's repository:

sudo apt update
sudo apt install ca-certificates curl

Create the directory where Ubuntu can store Docker's signing key:

sudo install -m 0755 -d /etc/apt/keyrings

Download Docker's official signing key:

sudo curl -fsSL https://download.docker.com/linux/ubuntu/gpg \
  -o /etc/apt/keyrings/docker.asc

Make the key readable:

sudo chmod a+r /etc/apt/keyrings/docker.asc

Now add Docker's repository:

sudo tee /etc/apt/sources.list.d/docker.sources <<EOF
Types: deb
URIs: https://download.docker.com/linux/ubuntu
Suites: $(. /etc/os-release && echo "${UBUNTU_CODENAME:-$VERSION_CODENAME}")
Components: stable
Architectures: $(dpkg --print-architecture)
Signed-By: /etc/apt/keyrings/docker.asc
EOF

Update the package information again:

sudo apt update

Docker Engine can now be installed from Docker's official repository.

Install Docker

Install Docker Engine and its supporting components:

sudo apt install docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin

Verify that Docker is running:

sudo systemctl status docker

You should see:

active (running)

Press:

q

to leave the status screen.

Docker's official Ubuntu installation guide:

https://docs.docker.com/engine/install/ubuntu/

Test Docker

Let's make sure Docker actually works.

On each machine, run:

sudo docker run hello-world

Docker should download the hello-world image and start a container.

If you see Docker's confirmation message, that node is ready to run containers.

Repeat the test on:

node1
node2
node3

Running Docker Without sudo

Right now, we need to write:

sudo docker ...

We can optionally allow our user account to communicate with Docker without sudo.

Add your current user to the docker group:

sudo usermod -aG docker $USER

Then log out and back in, or restart the VM.

Afterward, test:

docker version
Warning

Membership in the docker group effectively gives the user root-level privileges through Docker.

We're using it here to make our local learning environment easier to work with.

Repeat this on all three nodes if you want to run the lab commands without sudo.

Check the Hostnames

Now let's make sure we can distinguish our machines.

On each VM, run:

hostname

We should have:

node1

node2

node3

Each node is an independent machine with its own operating system and Docker Engine.

Find the IP Addresses

Our nodes also need to communicate over the network.

On each machine, run:

ip addr

Look for the IP address belonging to the main network interface.

Depending on the hypervisor and Linux configuration, the interface might have a name such as:

ens33
ens160
enp1s0

The exact name isn't important.

We're interested in the node's IPv4 address.

For example:

node1    192.168.x.x
node2    192.168.x.x
node3    192.168.x.x

Your addresses will probably be different.

Important

Write down the IP address of each node.

We'll need them when creating the Docker Swarm.

Can the Nodes Communicate?

Before introducing Docker Swarm, let's verify something simpler:

Can our three machines actually reach each other?

From node1, try pinging the IP address of node2:

ping <node2-ip>

For example:

ping 192.168.100.20

Stop the command with:

Ctrl + C

Then test node3:

ping <node3-ip>

We can also test communication in the opposite direction.

From node2:

ping <node1-ip>

If the nodes can reach each other, our basic network is working.

node1 ←→ node2
  ↑         ↑
  └──→ node3
Note

If the nodes cannot communicate, don't continue to Docker Swarm yet.

Check the virtual machine network configuration first.

Docker Swarm Networking

Docker Swarm requires several types of communication between its nodes.

Docker uses the following ports by default:

Port Protocol Purpose
2377 TCP Swarm management
7946 TCP/UDP Communication between nodes
4789 UDP Overlay network traffic

These ports need to be reachable between the nodes participating in the Swarm.

For our local VM environment, the important thing is that the three machines can communicate with each other over their virtual network.

Warning

Swarm networking ports should be available between trusted Swarm nodes, not unnecessarily exposed to untrusted networks.

Docker's Swarm networking requirements:

https://docs.docker.com/engine/swarm/swarm-tutorial/

  • Access the network

We still don't have a Docker Swarm.

node1        node2        node3
Docker       Docker       Docker

Independent   Independent   Independent

Nothing is coordinating them yet.
